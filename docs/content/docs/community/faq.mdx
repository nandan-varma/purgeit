<Accordions type="single">
  <Accordion title="What is a project, and what is dormant?">
    A project is the nearest git repository (worktrees fold into their main repository) or a manifest folder outside git. It is dormant when git's log shows no commit, checkout or pull for 30 days (`dormantAfter` changes that). See [Projects and dormancy](/docs/concepts/how-it-works#projects-and-dormancy).
  </Accordion>
  <Accordion title="Why are some artifacts hidden in the UI?">
    Artifacts under 10 MB are folded away so the list shows what matters; the header says how many and how much. Press `m` to show them, or pass `--min-size` to set your own floor.
  </Accordion>
  <Accordion title="Why was a folder named target (or out, coverage, venv) not matched?">
    Those names are also used for authored folders, so they only match with proof: `target` beside a `Cargo.toml` or `pom.xml`, `out`/`coverage`/`.cache` beside a project manifest, `venv` containing a `pyvenv.cfg`. `purgeit explain <path>` says exactly what is missing.
  </Accordion>
  <Accordion title="Is anything deleted without asking?">
    No. The UI needs an explicit selection plus `y`; `clean` asks unless you pass `--yes`; without a terminal it refuses to delete unless you pass `--yes`.
  </Accordion>
  <Accordion title="Why was an artifact skipped?">
    `clean` and the UI print the reason: modified within `--min-age`, changed after the scan, protected (nested repo, deploy keypair, git-tracked files), or no longer claimed by a rule. See the [list of reasons](/docs/guides/clean-safely#when-something-is-skipped).
  </Accordion>
  <Accordion title="Why is the size smaller than du?">
    purgeit reports space that deleting would actually free. Files hardlinked to something outside the artifact (pnpm's content store) aren't counted. See [How sizes are counted](/docs/concepts/how-it-works#how-sizes-are-counted).
  </Accordion>
  <Accordion title="Why didn't it find my build folder?">
    `build` is only matched beside a manifest (`package.json`, `Cargo.toml`, …). Run `purgeit rules` to see the proof each gated rule needs, or [add your own rule](/docs/guides/custom-rules).
  </Accordion>
  <Accordion title="“N directories could not be read”">
    Permission errors and directories that vanish mid-scan are skipped and counted, never hidden.
  </Accordion>
  <Accordion title="The UI says it needs a terminal">
    You are in a pipe, a CI job or a script. Use [`scan` and `clean`](/docs/reference/cli).
  </Accordion>
  <Accordion title="Can I undo a deletion?">
    No — artifacts are regenerable, which is why the rules are strict. `purgeit history` lists what was removed.
  </Accordion>
  <Accordion title="Does it phone home?">
    No. There is no telemetry and no network access.
  </Accordion>
  <Accordion title="Windows and macOS specifics">
    Both are supported. Space is measured from allocated blocks on every platform; `git` is needed only for the tracked-files check.
  </Accordion>
</Accordions>

## It deleted something it shouldn't have

Please [open an issue](https://github.com/nandan-varma/purgeit/issues) with `purgeit history --format json` and the rule that matched. Safety bugs are treated as top priority.
